# 에이전트 면접 앱

`apps/interviews`의 독립된 Next.js App Router 앱이다. workspace 이름은 `@cgbg/interviews`, 개발·프로덕션 기본 포트는 3001이다.

루트에서 `npm run dev:interviews`로 실행한다. 서버 전용 `ANTHROPIC_API_KEY`, `INTERVIEW_SESSION_SECRET`(32자 이상)을 앱의 `.env.local`에 설정한다. 기본 모델은 `claude-sonnet-4-6`이다. 비밀 키 생성 명령은 [README](../../README.md#면접-앱-실행)를 따른다.

`@/*`는 이 앱의 `src/*`를 가리킨다. Supabase는 `@cgbg/shared/supabase/client` 또는 `@cgbg/shared/supabase/server`를 사용한다. 필요할 때 앱 내부 `.env.example`을 `.env.local`로 복사한다.

전체 실행·검증·배포는 [README](../../README.md), 기능 방향은 [제품 아이디어](../01_product_idea.md)를 따른다.

앱 간 구직자 프로필 형식은 [프로필 데이터 계약](../shared/00_profile_contract.md)을 따른다.

## 현재 동작

면접 진행 화면은 기업별 가로 카드가 순차적으로 나타나는 목록이다. 현재 단계·최신 발화·메시지 수를 갱신하며, 사전검토 통과 기업은 상단에 유지한다. 탈락·보류·실행 오류 기업은 위 목록에서 빠져 하단 회색 카드로 모인다. 비활성 카드에도 마지막 발화의 단계와 제외·보류·오류 사유를 남긴다. 각 카드에서 상세 이유와 전체 대화를 펼쳐 볼 수 있다. 통과 카드의 **면접 일정 잡기 →**는 기존 시연용 신청 상태를 브라우저에 저장하며 실제 캘린더와 연동하지 않는다.

면접 앱은 사이드바 없이 본문 중심으로 표시한다. 백지오 페르소나를 선택하면 프로필 요약 화면에서 경력·주요 역량·희망 직군·관심사·검색 국가를 먼저 확인한다. 이 화면의 **면접 시작**을 누르면 캐시 재생과 진행 현황 화면으로 이동한다.

체험 흐름은 **페르소나 선택 → 프로필 준비 → 검색어 추출 → 기업 검색 → 동시 면접·후보 추림 → 면접 신청**이다. 백지오 선택 후 시작하면 `GET /api/demo`에서 저장된 공개 이벤트를 받아 검색 단계는 처음 12초 동안 순서대로 보여주고, 이후 이벤트 수에 맞춰 진행률을 계산해 면접 시작 후 약 100초에 전체 결과를 표시한다. 0.25초마다 경과 시간에 맞춰 따라잡으므로 일반적인 타이머 지연이 누적되지 않는다. 네트워크 지연·백그라운드 탭의 실행 정지 시간은 브라우저 환경에 영향을 받는다. 추가 Claude 요청은 없다. 이 체험은 미국 조건으로 고정되며 화면을 떠나면 재생이 멈춘다. 내 페르소나는 온보딩 완료 후 국가를 선택하고 서버에서 실제 파이프라인을 실행한다.

‘AI 사전검토 통과’는 핵심 역량이 맞아 사람과 면접할 가치가 있다는 평가다. 연봉·근무 조건 미확정은 별도로 표시하고 그것만으로 보류하지 않는다. 필수 역량의 근거 부족은 보류, 명확한 필수 역량·수락 불가능한 조건 불일치는 불일치로 남긴다. 실제 기업의 채용 합격이 아니다. 상단에 남은 통과 후보 카드에서 **면접 일정 잡기 →**를 누른다. 신청은 기업·실행 ID별 시연 상태만 브라우저 localStorage에 저장하며 개인정보를 추가 저장하지 않는다. 같은 브라우저에서 복원되지만 저장 데이터를 지우거나 다른 브라우저로 옮기면 유지되지 않는다. 기업 전송·캘린더 일정 조율은 없다.

첫 화면에서 백지오 예시 또는 내 페르소나를 선택한다. 선택만으로 서버 면접을 시작하지 않으며, 기록 URL로 접속하면 선택 화면을 건너뛰고 기록을 복원한다. 내 페르소나에서는 공유 온보딩 화면에서 이력서·질문·희망 조건으로 프로필을 만들고 결과를 확인해 면접 준비 화면으로 이동한다. `POST /api/onboarding/parse`는 독립 온보딩 앱과 같은 파서를 사용한다. 생성 파일은 기존 폴더 업로드와 같은 v1 검증을 통과해야 하며 비공개 Markdown은 면접 입력에서 제외한다. 프로필은 면접 시작 전까지 메모리에만 유지된다. 기존 폴더는 온보딩 하단에서 업로드하고 확인 체크 후 **이 프로필로 면접 준비하기**로 진입할 수 있다. 면접 시작을 누르면 업로드한 프로필로 실제 Claude가 검색어를 추출한다. 자료가 없으면 샘플로 체험할 수 있다. 실제 공개 공고 17,237건에 국가 필터(화면 기본값은 프로필 국가, API 생략 시 전체)를 적용한다. 제목 3점·본문 1점의 대소문자 무관 부분 일치와 연봉 표기 1점으로 정렬한다. 키워드 일치가 없으면 연봉 가산점도 없다. 동점은 풀 순서를 유지한다. 회사명 중복을 제거하고 최대 100곳을 골라 모두와 동시에 면접한다. 약 90%는 주 직군, 10%는 전환·탐색 후보를 목표로 한다. 탐색 검색어는 구체적인 직업명이며 공고 제목 일치가 필수다. 선언된 주 직군과 같은 직업군(개발·연구직 포함)을 탐색으로 다시 세지 않는다. 명시된 짧은 핵심 기술명과 교육·커뮤니티·콘텐츠 활동, 커피·음악 관심사에서 검색 표현을 보완한다. 관심사만으로 경력이나 자격을 만들어내지 않으며, 유효한 관심사 후보가 있으면 탐색 슬롯 중 최소 한 곳에 포함한다. 근거 활동 기반(evidence)과 관심사 기반(interest)을 구분하고 가설을 기록한다. 관심사 기반은 적합성 확인 필요로 표시한다. 탐색 후보가 부족하면 주 직군으로 남은 슬롯을 채우며, 전체 일치 공고가 부족하면 100곳 미만이다. 실제 구성 수를 검색 통계와 후보 목록에 표시한다. 일치가 없으면 정상 종료한다. 검색 대상·일치 공고·기업 수와 국가를 화면과 실행 기록에 남긴다.

기업별로 독립된 대화 이력을 만든다. 고정 질문 순서 없이 양측 에이전트가 다음 질문·반문·조건 조율과 종료 시점을 결정한다. 채용 에이전트가 응답의 stage로 현재 주제를 표시한다. MAX_TURNS는 양측 개별 발화 수의 합계이며 기본 20(최대 10왕복), 서버에서 1~100 정수로 설정한다. 남은 발화 예산을 모델에 전달하며 한도 도달 시 강제로 대화를 마무리한다. 어느 한쪽이 done=true를 반환하거나 사용자 확인이 필요하면 조기 종료한다. 최종 평가는 한도 밖에서 1회 수행한다. 선정된 최대 100개 기업은 Promise.all로 동시에 시작하고 한 기업의 오류가 다른 기업을 중단시키지 않는다. 정보가 부족하면 확인 질문과 보류 결과를 남긴다. 사용자 답변 제출·재개와 일정 조율은 아직 없다. 추천은 실제 채용 합격이 아니다.

`src/workflows/interviews.ts`가 실행을 조율하고 `src/lib/steps.ts`가 파일 읽기·Claude 호출·진행 기록을 담당한다. 프론트엔드는 저장된 NDJSON 진행 기록을 읽어 갱신하며 재접속 시 처음부터 복원한다. 명시적 중지는 서버 실행을 취소한다. 이미 전송된 Claude 요청의 비용까지 취소된다고 보장하지 않는다.

## 샘플 입력과 프로필 v1

계약 타입은 `@cgbg/shared/profile`, 런타임 검증은 앱의 `schemas.ts`에 있다. 샘플은 저장소 루트 `data/demo/candidates/onboarding-example/`의 최신 온보딩 예시 한 곳에서 읽는다. 버튼 체험과 폴더 업로드 모두 같은 v1 검증을 적용한다. 앱 내부에 예시 복사본을 만들지 않는다. 아래 경로는 예시 폴더 기준이다.

```text
index.json
public/experience.md
public/strengths.md
private/interview.md
```

구직자 `index.json`은 `confirmed_at`(ISO 시각), `salaryPeriod: "annual"`, `publicProfile: PublicProfile`, `privateProfile: PrivateProfile`을 묶는 **면접 앱 입력 봉투 형식**이다. 온보딩은 이 형식의 폴더를 생성하며 통합 화면에서는 메모리로 바로 전달한다. 독립 온보딩 앱에서는 zip을 내려받아 압축을 풀고 면접 앱에서 선택한다. 두 프로필 ID가 같아야 한다. 프로필과 공개 문서를 시작 시 실행 입력 스냅샷으로 보관한다. 서버는 확인 후 시작한 시각으로 `confirmed_at`을 갱신한다.

폴더 전체는 파일 20개·합계 1MB 이하이며, index에 등록한 Markdown 파일과 index.json만 허용한다. 누락·중복·경로 이탈·없는 근거 앵커는 시작 전에 안내한다. 폴더 선택은 브라우저에서 읽기·미리보기만 수행하며, 시작할 때 프로필 JSON과 공개 문서 내용만 서버로 전송한다. 비공개 Markdown 원문은 전송하지 않는다. 서버에서 같은 검증을 다시 수행하고 요청 본문도 1MB로 제한한다. PDF·원본 이력서의 프로필 변환은 같은 앱의 공유 온보딩 화면에서 수행한다.

실제 공고는 `src/data/jobs/jobs_pool.json.gz`의 스냅샷이다. 원본 필드는 `id`, `title`, `company`, `country`, `location`, `salary`, `source`, `url`, `text`다. 제공자는 Greenhouse·Ashby·Lever 공개 API와 LinkedIn·사람인·잡코리아에서 수집했다고 밝혔다. 전체 17,237건, 미국 8,759·한국 947·호주 172건, 연봉 표기 2,666건이다. JD는 앞 약 2,500자만 포함하며 현재 모집 여부는 원문에서 확인해야 한다.

`src/lib/searchJobs.ts`는 검색 step 안에서만 압축 풀을 읽고 검증해 프로세스 메모리에 캐시한다. 기본 경로는 앱 cwd 아래 `src/data/jobs/jobs_pool.json.gz`이며 서버 `JOBS_POOL_PATH`로 변경한다. Vercel 함수 추적에 파일을 포함했다. 전체 풀과 미선정 목록은 Workflow 입력·출력에 직렬화하지 않는다. 화면에는 `summary.json`의 국가별 개수만 포함한다. 풀 교체 시 요약도 함께 갱신한다.

공고는 검색·Workflow·양측 에이전트·화면에서 원본 필드 `id/title/company/country/location/salary/source/url/text`를 그대로 사용한다. `salary`는 원문 문자열이고 빈 값은 미기재다. 타입과 런타임 검증은 같은 `jobSchema`를 기준으로 한다. 별도 description·skills·salaryText·remote·weeklyHours 필드는 만들지 않는다. 화면에서 제공된 JD 일부·출처·원문 링크·연봉을 확인한다. 정규화된 연봉·근무 조건이 없으므로 통화·지급 주기·시간·원격 여부를 추정하거나 하한과 숫자로 비교하지 않는다. 모델의 사전검토 결과를 보존하고 미확정 원문 조건을 별도 확인 사항으로 덧붙인다. 기존 실행 기록의 description·salaryText는 재생 시 원본 필드로 변환한다.

샘플 구직자는 저장소에 제공된 온보딩 예시이며 공고는 실제 공개 자료다. 공개 문서만 읽고 루트 이탈·상위 경로 이동·잘못된 JSON·누락 근거와 앵커를 거부한다. 비공개 Markdown 원문은 모델에 넣지 않고 구조화된 비공개 조건만 구직자 프롬프트에 사용한다. 연봉 하한은 양측 모델과 공개 진행 기록에서 제외한다. 원문 연봉을 정규화하는 비교 기능은 아직 없다. 채용 에이전트는 공개 요약·공개 문서·자기 공고·해당 기업 대화만 받는다.

## 실행·저장·접근 제어

Workflow SDK 5.2.3의 실행 로그와 저장 스트림을 사용한다. 로컬은 앱의 `.workflow-data/`에 저장하며 서버 프로세스가 켜져 있어야 진행된다. 폴더를 삭제하면 기록을 잃는다. Vercel에서는 관리형 Workflow로 두 기업의 실제 면접 완료와 기록 조회를 확인했다. 다른 서버리스 호스트에서 로컬 파일 저장으로 운영하지 않는다. 온보딩 zip → 압축 해제 → 폴더 업로드로 전달한다. Supabase 테이블·온보딩 데이터 직접 조회·자동 앱 이동은 아직 연결하지 않았다. 기존 계획의 Supabase 상태 복제는 샘플 구현에 포함하지 않는다.

실행 ID만으로 조회할 수 없다. 서버가 실행 ID와 만료 시각을 서명한 HttpOnly·SameSite 쿠키를 발급하고 조회·중지 시 검증한다. 새 실행 시 쿠키가 교체되므로 같은 브라우저의 **가장 최근 실행 1개**를 24시간 동안 복원한다. 제어 토큰·프로필을 URL에 넣지 않는다. Workflow 내부 로그에는 비공개 프로필이 있으므로 관리자 접근을 제한해야 한다.

| API | 동작 |
| --- | --- |
| `POST /api/runs?country=AU` | country 생략 시 전체 국가. 업로드한 입력 JSON으로 시작, 본문이 없으면 샘플 시작. 진행 중인 실행이 있으면 새 프로필 요청은 409, 샘플 요청은 같은 ID 반환 |
| `GET /api/runs/{id}` | 실행 상태 |
| `GET /api/runs/{id}?stream=1` | 공개 이벤트 재생·실시간 수신 |
| `DELETE /api/runs/{id}` | 실행 취소 |

변경 요청은 같은 출처에서만 허용한다. 새 실행은 프로세스·IP당 분당 1회, 공고 최대 100개, 기업별 MAX_TURNS=20개 발화, 호출당 출력 최대 900토큰·60초 타임아웃이다. 기본 설정의 최악 실행은 키워드 1회 + 기업당 대화 20회·평가 1회로 최대 2,101번의 Claude 요청이다. 조기 종료되면 줄어든다. 실제 동시 처리량은 Claude 계정과 Workflow 플랫폼의 실행 한도에 영향을 받으며, 현재 API 오류·429는 해당 기업 오류로 표시하고 자동 재시도하지 않는다. SDK와 모델 step의 오류 자동 재시도는 끈다. 장애 시 외부 요청의 중복 비용이 절대 없다고 보장하지 않으며 입력·이력 토큰도 과금된다. 전체 배포의 금액 상한·공유 동시 실행 제한은 아니므로 공개 운영 전 Firewall 또는 공유 제한과 API 사용량 한도가 필요하다.

## 검증과 후속 작업

### 백지오 체험용 실행 캐시

src/data/demo/gio-interview.json은 2026-10-24 실제 Claude 실행의 공개 이벤트 763개를 담는다. 미국 공고 8,759건에서 1,047건·80개 기업이 검색됐고, 회사 중복과 탐색 비율을 적용해 76곳(주 직군 68·전환 탐색 8, 약 10.5%)을 선정했다. 최대 한도는 100곳이며 관련 공고가 부족하면 억지로 채우지 않는다. 바리스타는 관심사 기반 가설로, 커뮤니티·기술 문서·교육 직군은 활동 근거와 함께 표시한다.

76곳의 실제 평가와 대화 311개를 저장했다. 합의된 AI 사전검토 기준으로 최종 평가만 갱신한 결과는 사전검토 통과 3·확인 필요 11·불일치 62다. 원래 대화 311개는 유지했다. 발화 한도는 20이며 실제 최장 대화는 10개 발화에서 조기 종료됐다. 시연을 위해 결과를 합격·추천으로 바꾸지 않았다. 공개 프로필 스냅샷·검색어·선정 공고·진행 단계·질문·평가를 포함하고 비공개 프로필·연봉 하한·접근 쿠키는 제외한다.

로컬 Workflow 실행 중 Step not found 오류와 개발 서버 종료가 발생해, 수집된 대화 116개부터 동일한 에이전트 함수를 직접 병렬 실행해 이어갔다. 마지막 응답 형식 오류 1곳만 별도로 재개했으며 최종 캐시는 오류 0개·평가 76개로 확인했다. 메타데이터의 resumedWithDirectAgents와 retriedJobIds가 생성 경로를 표시한다. 이 캐시는 로컬 Workflow 또는 Vercel의 100개 동시 실행 안정성을 검증한 결과가 아니다. 고정 3왕복은 제거했고, 100개 동시 스케줄링·한도·조기 종료 로직은 별도 모의 테스트로 확인했다.

모델이 종료 필드를 생략하면 기본값 false로 이어가되 발화 한도는 지킨다. 출력 토큰 한도에서 잘린 응답은 정상 데이터로 저장하지 않는다. 프로필이나 공고 풀을 바꾸면 캐시를 다시 생성한다. 체험 UI의 지연 재생을 연결했다. 이번 변경의 배포는 아직 진행하지 않았다.

유닛 테스트는 계약·업로드 검증·프롬프트 경계·스크리닝·상태 복원·서명을 검사한다. E2E는 테스트용 Claude HTTP 서버와 실제 Workflow 런타임으로 사용자 폴더 선택·확인·서버 대화 입력·창 닫기·서버 완료·재접속·권한을 확인한다. 모의 응답은 앱 실행 코드에 없다.

실제 Claude의 두 기업 병렬 면접은 로컬과 [Vercel 프로덕션](https://cgbg-interviews.vercel.app)에서 확인했다. 2026-10-24 클라우드 확인에서는 화면 연결 없이 시작한 작업이 완료됐고, 키워드 추출·스크리닝·연봉 협상을 포함한 대화 12개와 기업별 추천 결과 2개를 저장 기록으로 조회했다. 실행 오류와 연봉 하한 노출은 없었다. 서버 장애 복구·Supabase 연결은 미검증이다. 설치·환경변수·Git 연결 상태는 [README](../../README.md#vercel-배포)를 따른다. 후속 작업은 온보딩 확정 프로필 연결, 사용자 질문 응답·재개, 기업별 재시도다. 전체 방향은 [개발 계획](../plan/20261024_1132_onboarding_agents_plan.md)을 참고한다.

Workflow의 간접 의존성 Zod·Undici에서 npm audit의 high 경고 23건을 확인했다. 호환 범위의 자동 수정으로 해소되지 않았으며, 공개 운영 전 의존성 업데이트와 재검토가 필요하다.

회사명이 빈 원본 공고는 풀과 국가별 총수에는 포함하지만 기업 식별이 불가능해 면접 검색 결과에서 제외한다.

검색 단계 하단에 추출한 실제 검색어 목록을 로그로 표시한다. 별도 공개 공고 안내와 국가별 일치 공고 통계 문장은 표시하지 않는다. 체험 속도 안내는 4배속으로 표시한다.

하단 목록은 확인 후 결정(hold) 기업을 명확한 불일치·오류보다 먼저 표시한다. 통과는 초록색, 보류는 노란색, 불일치·오류는 빨간색 배지로 구분한다. 비활성 카드도 전체 투명도를 낮추지 않아 상태·단계·사유를 읽을 수 있다.

기업 카드 로고는 `src/data/company-domains.json`에 등록한 공식 사이트의 아이콘을 `public/company-logos/`에서 제공한다. 2026-10-24에 Google의 공개 사이트 아이콘 캐시(`https://www.google.com/s2/favicons?domain={공식 도메인}&sz=128`)로 샘플 76개 기업 아이콘을 가져와 PNG로 보관했다. 실행 중 외부 로고 서비스나 공고 사이트 호스트로 요청하지 않는다. Hilton 공고는 호텔 그룹 아이콘을 사용한다. 미등록 기업·이미지 로딩 실패는 이니셜로 표시하며, 새 기업을 지원하려면 공식 도메인과 해당 PNG를 함께 추가한다. 로고 권리는 각 기업에 있다.

# 제품 아이디어: 구직자와 채용 에이전트의 사전 면접

## 선택한 주제와 문제

선택한 해커톤 주제는 **AI로 사라질 직업 1,000만 명을 구할 제품**이다. 여기서 1,000만 명은 주제에 제시된 목표이며, 검증된 시장 규모나 제품 성과를 뜻하지 않는다.

구직자는 수백·수천 곳에 이력서를 반복 제출하며 오랜 시간을 쓴다. 채용 담당자 역시 많은 지원서를 검토해야 하므로 학벌 같은 간접 지표에 의존하기 쉽다는 것이 팀의 문제 가설이다. 이력서 제출과 서류 검토만으로는 실제 역량, 희망 조건, 업무 적합성을 충분히 확인하기 어렵다.

## 솔루션과 핵심 경험

구직자를 이해한 에이전트와 기업의 직무·조건을 이해한 채용 에이전트가 먼저 대화한다. 경력의 근거와 서로의 조건을 확인하고, 사람 간 면접을 진행할 만한 후보와 기업을 연결한다.

**WOW point: 지원 버튼을 반복해서 누르지 않고, 나에게 맞는 기업과의 면접으로 이어진다.**

현재 직무명만으로 기업을 찾지 않는다. 관심사, 과거 경험, 다른 직무에도 활용할 수 있는 역량을 참고해 전환 가능한 역할도 탐색한다. 실제 사람 간 면접 초대와 채용 결정은 당사자의 확인이 필요한 별도 단계다.

## 서비스 흐름

자료 입력은 `index.json`을 포함한 구직자·채용공고 폴더를 기준으로 한다. 앱 간 프로필은 [프로필 데이터 계약 v1](shared/00_profile_contract.md)의 공개·비공개 구분을 따르며, 실제 자료 폴더와 manifest·공고 형식은 아직 준비 전이다. 구직자 에이전트가 자료에서 검색 키워드를 추출해 공고를 스크리닝하고, 선정한 공고마다 채용 에이전트를 생성해 1:N 면접을 진행한다. 기업별 대화는 분리하며 면접은 프론트엔드와 무관하게 서버에서 계속 실행한다. 상세 구현 순서는 [온보딩·면접 실행 계획](plan/20261024_1132_onboarding_agents_plan.md)을 따른다.

### 1. 구직자 온보딩

이력서, Notion, GitHub, 포트폴리오, SNS 등 개인 자료를 제공한다. 구직자 에이전트는 자료에서 알 수 없는 희망과 조건을 인터뷰로 확인한다.

- 어떤 유형의 일을 하고 싶은가?
- 희망 연봉과 조정 가능한 조건은 무엇인가?
- 면접에서 꼭 강조하고 싶은 강점은 무엇인가?

경력, 역량, 관심사, 선호 조건, 양보할 수 없는 조건을 정리하고 각 정보의 근거를 남긴다. 사용자가 확인하고 수정한 프로필을 다음 단계에 사용한다. 정보가 없으면 추측하지 않고 확인 질문으로 남긴다.

정보의 관계를 그래프로 보여주는 아이디어는 열어두되, 그래프 DB나 시각화 도입은 아직 확정하지 않았다.

### 2. 에이전트 간 면접

대시보드에서 후보기업 검색과 개별 면접 진행 상황을 보여준다.

| 표시 | 의미 |
| --- | --- |
| 후보기업 검색 중 | 경력·관심사·전환 가능한 역량을 참고해 채용공고 탐색 |
| 인터뷰 진행 중 | 구직자 에이전트와 채용 에이전트가 실제 대화 중 |
| 경험 조회 중 | 주장한 역량을 제공된 자료의 근거와 대조 |
| 연봉 협의 중 | 구직자와 채용공고의 조건을 비교하고 조정 가능성 확인 |
| 사용자 확인 필요 | 에이전트가 대신 결정할 수 없는 조건에 대해 질문 |

기업별 대화, 확인한 근거, 조건 차이와 결과 이유를 열어볼 수 있다. 에이전트가 임의로 경력이나 수락 의사를 만들어내지 않는다.

- 면접 추천: 사람 간 면접을 진행할 만한 적합성이 확인된 상태.
- 보류: 정보가 부족하거나 사용자의 응답을 기다리는 상태.
- 조건 불일치: 어느 조건이 맞지 않는지 설명하는 상태. 실제 채용 불합격 통보를 뜻하지 않는다.

사용자에게는 “이 역할에는 XXX 업무도 포함됩니다. 수행할 의향이 있나요?”처럼 선택이 필요한 질문을 보낸다. 근무시간 등 명시한 필수 조건과 충돌하면 그 근거를 보여주며, 새로운 양보나 거절 의사가 필요하면 사용자에게 확인한다.

### 3. 사람 간 면접 조율

면접 추천 결과를 사용자가 확인한 뒤, 채용 담당자와 구직자의 캘린더를 참고해 시간을 제안하고 확정한다. 최종 서비스의 확장 단계이며 첫 MVP에서는 실제 캘린더 연동을 제외하는 안을 제안한다.

## 확정한 첫 데모 범위

| 항목 | 범위 |
| --- | --- |
| 구직자 | 가상 구직자 1명, 로그인 없이 시연 |
| 기업과 공고 | 준비된 샘플 기업·채용공고 사용 |
| 면접 | 실제 Claude API 대화 사용; 고정된 대화 재생으로 대체하지 않음 |
| 앱 구성 | 온보딩과 면접 진행 화면을 각각 독립된 Next.js 앱으로 구성 |

## 첫 데모 구성 제안

위 표의 네 항목은 확정 사항이다. 아래 세부 흐름과 제외 범위는 검토할 제안이며, [개발 계획](plan/20261024_1119_monorepo_plan.md)을 확인한 뒤 구현 범위를 확정한다.

1. 준비된 가상 이력서를 불러와 Claude의 희망 조건 인터뷰를 진행한다.
2. 확인한 프로필을 저장하고 면접 앱으로 이동한다.
3. 소수의 샘플 공고에 대해 실제 에이전트 대화와 근거를 확인한다.
4. 면접 추천·보류·조건 불일치 결과와 추가 질문을 확인한다.

실제 개인 자료 수집, 외부 서비스 자동 수집, 실제 구인 사이트 연동, 채용 담당자 화면, 실제 지원·거절 통보와 캘린더 예약은 첫 데모에서 제외하는 안이다. 실제 구직자 서비스를 만들 때 별도로 범위를 확정한다.

## 데모에서 지킬 표현

실제로 실행한 기업 수와 진행 상태를 표시한다. “314개 기업” 같은 숫자는 시각적 예시이며 실제 처리 없이 실적으로 표시하지 않는다. 샘플 기업과 가상 구직자라는 점을 명시하고, “면접 추천”을 실제 기업의 면접 초대나 채용 확정으로 표현하지 않는다.

각 결과는 직무 요구사항과 자료의 근거로 설명한다. 학벌 순위 같은 대리 지표만으로 적합성을 판단하는 흐름은 만들지 않는다.

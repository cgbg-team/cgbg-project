# 프로젝트 개요

## 목적

Anthropic 해커톤에서 공개되는 주제를 바탕으로 빠르게 프로젝트 개발을 시작하기 위한 보일러플레이트다. Next.js, Vercel, Supabase 기반의 초기 구조와 개발 규칙을 준비해 주제 확정 후 구현 과정의 시행착오를 줄인다.

## 확정 기술 스택

| 기술 | 역할 |
| --- | --- |
| Next.js | 웹 애플리케이션 프레임워크 |
| Vercel | 애플리케이션 배포 및 호스팅 |
| Supabase | 데이터베이스 및 필요한 백엔드 기능 |

스택은 확정되어 있다. Next.js App Router, TypeScript, Tailwind CSS, ESLint, npm 기반 초기 구조와 Vitest·Playwright 테스트 설정을 제공한다. Supabase는 서버·브라우저 클라이언트와 환경변수 예시까지만 준비하며, 실제 클라우드 리소스 연결은 아직 완료되지 않았다.

실행과 설정은 [README](../README.md), 에이전트 작업 규칙은 [AGENTS.md](../AGENTS.md)를 따른다. 로그인, 세션 갱신, DB 스키마와 주제별 기능은 요구사항 확정 후 구현한다.

## 개발 범위

주제 공개 전에는 주제에 종속되지 않는 최소 초기 구조를 준비한다. 주제 공개 후에는 개발자가 확정한 요구사항을 구현하며, 요청하지 않은 기능이나 추측에 기반한 확장을 추가하지 않는다.

요구사항의 기능 범위나 완료 기준이 모호하면 개발자에게 질문해 확정한 뒤 구현한다. 확정 범위 안의 구현 선택은 에이전트가 결정할 수 있다. 다만 대안 간 개발 시간이나 복잡도에 상당한 차이가 있으면 선택 전에 개발자에게 확인한다.

## 코드 및 테스트 제한

- 직접 작성하거나 관리하는 코드 파일은 파일당 500줄 이하로 유지한다. 빈 줄과 주석도 줄 수에 포함하며, 자동 생성물과 잠금 파일은 제외한다.
- 테스트 제한은 프로젝트 전체의 실행 테스트 케이스 수를 기준으로 한다. 매개변수화 테스트의 각 케이스도 별도로 센다. 유닛 테스트는 100개 이하, End-to-End(E2E) 테스트는 20개 이하로 유지한다.
- 제한에 도달하면 기존 코드와 테스트를 검토해 분리·통합·중복 제거를 진행한다. 필요한 검증을 생략하거나 테스트를 임의로 삭제하지 않으며, 제한 내에서 해결하기 어려우면 개발자와 범위를 조정한다.

## 언어 정책

- 문서, 코드 주석, 개발자와의 대화는 한국어를 사용한다.
- 커밋 메시지는 영어를 사용한다.
- 외부 참고 자료는 원문 언어를 유지한다.

## 해커톤 참고 자료

행사 안내는 [Ambition for Korea 영어 원문](etc/hackathon.md)에 보관한다. 제공된 안내문을 그대로 보존한 자료이며, 최신 공지 여부를 별도로 검증한 문서는 아니다.

실제 개발 주제는 행사에서 공개된다. 안내문에 등장하는 서비스 예시는 확정 요구사항으로 취급하지 않는다.

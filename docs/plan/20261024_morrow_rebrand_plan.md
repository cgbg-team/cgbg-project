# Morrow 리브랜딩 및 화면 통일 계획

상태: 로고·파비콘·공유 이미지, 두 앱의 공통 테마와 화면별 스타일, Morrow 표기를 코드에 적용했다. 배포 결과와 검증 상태는 작업 완료 보고를 따른다.

## 1. 목표와 현재 상태

서비스 이름을 **Morrow**로 통일한다. 내 경험을 이해하는 개인 에이전트가 다음 커리어 기회를 찾는 서비스라는 인상을 첫 화면부터 일정 완료까지 이어간다.

- 첫 화면·샘플 프로필: `cgbg.`와 문자 c 로고.
- 공유 온보딩: `BEYOND CV`, 흑백 Tailwind 스타일.
- 면접 결과·안내: `MORROW`, 녹색 기반 CSS.
- 두 앱의 브라우저 제목: `cgbg-project`. 기본 파비콘도 교체 대상이다.
- `apps/interviews` 안의 온보딩과 별도 `apps/onboarding`이 같은 공유 컴포넌트를 사용한다. 양쪽에서 같은 모습을 유지해야 한다.

## 2. 브랜드와 로고 방향

표기는 제목·본문·접근성 이름 모두 `Morrow`로 한다. 설명 문구는 기존 의미를 보존하고 서비스명만 일관되게 정리한다.

**제안 콘셉트: Next morning.** 두 개의 둥근 아치가 소문자 m과 수평선 위로 떠오르는 형태를 함께 만든다. 작은 크기에서도 구별되는 단순한 실루엣을 사용한다. 워드마크는 `Morrow`로 표기한다.

| 자산 | 용도와 완료 기준 |
| --- | --- |
| 심볼 | 16·24·32px에서 식별 가능, 정사각형 영역에 배치 |
| 가로 로고 | 심볼 + Morrow, 데스크톱·모바일 공통 헤더 |
| 단색·반전 버전 | 흰 배경·녹색 배경에서 동일한 형태 유지 |
| SVG 원본 | 확대·축소 가능한 벡터, 공유 Logo 컴포넌트에서 사용 |
| 파비콘·공유 이미지 | 두 앱의 탭 아이콘과 링크 미리보기에도 같은 브랜드 사용 |

로고 제작 시 기본형 한 개를 먼저 완성하고 첫 화면·온보딩 헤더·파비콘에 대입해 확인한다. 복잡한 마스코트나 로고 애니메이션은 이번 범위에 넣지 않는다.

## 3. 공통 스타일 기준

기존 녹색 분위기를 계승하되 작은 글씨와 화면마다 다른 컨트롤을 정돈한다. 아래 값은 구현 시작점이며 실제 화면 대비를 확인한 뒤 확정한다.

| 항목 | 제안 기준 |
| --- | --- |
| 배경 | 따뜻한 오프화이트 `#FAFBF7`, 콘텐츠 표면 흰색 |
| 주요 색 | 깊은 녹색 `#176342`, 본문 `#203A32` |
| 보조 색 | 세이지 `#EDF2E6`, 보조 글자 `#5F6F65`, 테두리 `#DDE5DC` |
| 상태 색 | 추천·대기·오류를 색과 텍스트로 함께 구분 |
| 타이포 | 두 앱의 한글·영문 폰트 스택 통일, 본문 16px 기준, 보조 14px, 제목 단계 통일 |
| 간격·형태 | 4px 기반 간격, 버튼 8px·카드 12px 모서리, 입력·버튼 최소 높이 44px |
| 인터랙션 | 동일한 hover·focus·disabled·pending, 짧은 전환, reduced-motion 지원 |
| 레이아웃 | 공통 헤더, 읽기·폼 화면 최대 720px, 면접 목록 최대 1440px, 모바일 여백 20px |

공통 CSS 변수와 실제 재사용하는 Logo·버튼·입력·상태 배지 스타일만 `packages/shared`에 둔다. 기존 Next.js·Tailwind·CSS를 사용하며 새 UI 프레임워크는 추가하지 않는다. 화면의 목적에 따라 정보 밀도는 다르게 유지한다.

## 4. 페이지 및 상태별 수정 범위

| 화면 | 수정 내용 | 주요 위치 |
| --- | --- | --- |
| 페르소나 선택 `/` | Morrow 로고, 공통 헤더·카드·CTA, 두 선택지의 위계와 모바일 여백 정리 | `persona-choice.tsx`, `styles/persona.css` |
| 백지오 프로필 `/` 내부 상태 | 같은 헤더·제목·프로필 섹션, 희망 조건·시작 CTA 스타일 통일 | `profile-summary.tsx`, `styles/profile.css` |
| 내 프로필 `/onboarding` | 4단계 진행 표시, 프롬프트·JSON·질문·완료 화면, 언어 전환과 폴더 업로드를 공통 스타일로 정리 | `own-onboarding.tsx`, 공유 `onboarding/` |
| 별도 온보딩 앱 `/` | 면접 앱에 내장된 온보딩과 같은 로고·폰트·컨트롤 적용 | `apps/onboarding/src/app/`, 공유 `onboarding/` |
| 면접 준비·진행·결과 `/?run=…` | 헤더·검색 필터·통계·진행 로그·결과 카드·Morrow의 조언 통일 | `interview-dashboard.tsx`, `run-progress.tsx`, `company-interviews.tsx` |
| 기업 상세·대화·일정 선택 | 기업 로고와 서비스 로고 구분, 상세 정보·대화·1시간 슬롯·선택 상태·확정 버튼 통일 | `interview-detail.tsx`, `interview-application.tsx`, `interview-calendar.tsx` |
| 완료 `/interview-complete` | 공통 브랜드 헤더, 중앙 🎉·축하 문구·일정 요약·캘린더 버튼, 일정 없음 상태 | `interview-complete.tsx`, `styles/calendar.css` |
| 공통 예외 상태 | 업로드 오류, JSON 오류, AI 처리 중·실패, 연결 끊김, 결과 없음, 저장 기록 없음 | 각 화면의 기존 상태 분기 |

두 앱의 `layout.tsx` 제목은 `화면 이름 | Morrow`로 정리하고 description·아이콘·공유 메타데이터도 맞춘다. 현재 실제 파일을 기준으로 하며 새 페이지나 기능을 만들지는 않는다.

## 5. 구현 순서

1. **브랜드 기반:** 로고 SVG·단색·반전·파비콘을 만들고 공유 Logo와 색상·타이포·컨트롤 스타일을 적용한다. 첫 화면과 온보딩 한 화면을 기준 화면으로 맞춘다.
2. **시작·온보딩:** 페르소나 선택 → 백지오 프로필 / 내 온보딩 → 프로필 완료까지 정리한다. 별도 온보딩 앱에도 같은 구현을 적용한다.
3. **면접·일정:** 준비 → 실행 → 결과 → 기업 상세 → 시간 선택 → 축하·캘린더 다운로드까지 같은 스타일을 확장한다.
4. **잔여 표기:** UI·접근성 이름·메타데이터·에이전트 복사 프롬프트·서버 프롬프트의 표시용 브랜드를 Morrow로 정리하고 관련 README·제품 개요를 갱신한다.
5. **마감 확인:** 390px·768px·1440px 화면과 키보드 조작을 확인하고 기존 테스트를 새 제목·표기에 맞춘다. 린트·타입·유닛 및 핵심 E2E 결과를 기록한다.

## 6. 호환성과 완료 기준

리브랜딩으로 기존 실행 기록·온보딩 프로필·면접 일정이 사라지면 안 된다. `@cgbg/*` 패키지명, API 경로, `beyond-cv/agent-export/v1` 계약, 브라우저 저장 키와 기존 캘린더 UID는 유지한다. 사용자에게 보이는 브랜드만 바꾼다. 기존 데이터의 일괄 재생성이나 DB 마이그레이션은 필요하지 않다.

- 모든 사용자 화면에서 서비스 이름은 Morrow다. 실제 기업 로고와 외부 출처 이름은 그대로 둔다.
- 두 앱에서 로고·폰트·색상·버튼·입력·포커스가 일관된다.
- 선택·진행·오류·빈 화면·완료 상태까지 포함해 모바일 가로 넘침이 없다.
- 기존 150개 데모와 내 프로필 연결, 시간대별 슬롯 선택, 일정 복원·캘린더 다운로드가 유지된다.
- 구현 완료와 배포 완료를 구분해 보고한다.

계획 수립 시 현황은 소스 기준으로 확인했다. 후속 구현에서 로고·테마를 적용했으며 추가 요청에 따라 기업 목록은 진행·통과 / 제외·보류 그룹 안에서 기업명 ABC 순으로 표시한다.
